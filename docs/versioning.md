# Web 앱 버전 정책

Digital Key Spec Intelligence Web 앱은 **`major.minor.patch`** 형식을 사용한다. 초기 버전은 **`0.1.0`**이다. 현재 첫 배포를 준비하는 과정의 제목·버전 표기 추가는 이 초기 버전에 포함하며, 아직 배포하지 않은 변경마다 버전을 올리지 않는다.

## 버전의 기준

Web 앱 버전의 단일 기준은 [`apps/web/package.json`](../apps/web/package.json)의 `version`이다. 화면은 이 값을 빌드 시 읽어 제작자 서명 footer 바로 위에 `Web v0.1.0`처럼 표시한다. 버전 문자열을 컴포넌트·환경변수에 따로 하드코딩하지 않는다. 버전 변경 뒤에는 새 빌드·배포가 필요하다.

합성 규격 데이터의 **V1/V2는 문서 버전**이며 Web 앱의 릴리스 버전과 독립적이다. 예를 들어 Web v0.1.1에서도 합성 V1/V2를 모두 검색할 수 있다. 루트 관리 패키지나 `spec-core` 패키지 버전도 Web 표시 값의 기준으로 사용하지 않는다.

## 증가 규칙

| 변경 | 올리는 자리 | 예시 |
| --- | --- | --- |
| 기존 사용 흐름이나 공개 API 계약을 호환되지 않게 변경 | Major | `0.1.0 → 1.0.0`, `1.4.2 → 2.0.0` |
| 기존 기능·API와 호환되는 사용자 기능 추가 | Minor | `0.1.0 → 0.2.0`, `1.4.2 → 1.5.0` |
| 버그·보안 수정, 호환성을 유지하는 UI·문구 개선 | Patch | `0.1.0 → 0.1.1`, `1.4.2 → 1.4.3` |

상위 자리를 올릴 때 하위 자리는 0으로 초기화한다. 여러 변경이 함께 나가면 가장 큰 변경 기준으로 한 번 올린다. 이 프로젝트는 `0.x`에서도 비호환 변경을 Minor로 숨기지 않고 Major로 올리는 보수적인 규칙을 사용한다. `1.0.0` 전환은 안정된 계약을 선언할 때도 명시적으로 결정한다.

커밋 수와 릴리스 수는 다르다. 구현·테스트·리팩터링 커밋마다 버전을 올리지 않으며, 다음 배포로 사용자에게 전달하는 변경 묶음에 대해 버전을 결정한다. 동작에 영향 없는 문서 수정이나 동일 소스의 재배포만으로는 올리지 않는다. 이미 배포한 버전의 동작을 바꾸면 새 버전을 부여한다.

## 릴리스 절차

1. 마지막 배포 이후 변경을 정리하고 Major/Minor/Patch 중 하나를 선택한다. 비호환 계약·흐름 변경은 사용자와 먼저 확정한다.
2. 저장소 루트에서 필요한 명령 **하나만** 실행한다.

   ```sh
   npm version patch --workspace @dksi/web --no-git-tag-version
   # 기능 추가 릴리스라면 patch 대신 minor
   # 비호환 릴리스라면 patch 대신 major
   ```

3. `apps/web/package.json`과 루트 `package-lock.json`의 해당 workspace 버전 변경을 함께 검토·커밋한다. 루트/다른 workspace 버전을 일괄 변경하지 않는다.
4. 릴리스 기록에 버전·주요 변경·알려진 한계·검증 결과를 남긴다. `npm run test`, `npm run lint`, `npm run build`를 실행하고, 검색·API 변경은 `npm run eval`, 화면/흐름 변경은 해당 브라우저 회귀도 확인한다.
5. 검증된 소스를 배포하고 실제 URL의 `Web vX.Y.Z`가 배포 대상 버전과 일치하는지 확인한다. 모델·배포 미확인 항목을 완료로 기록하지 않는다.
6. 필요하면 실제 배포 검증을 마친 커밋에 `web-vX.Y.Z` 태그를 붙인다. `--no-git-tag-version`을 사용하므로 버전 명령 자체는 커밋·태그를 자동 생성하지 않는다. Git push·배포는 Main Agent가 조율한다.

현재 릴리스 기준은 `0.1.0`이며 실제 배포 URL과 실모델 검증 결과는 별도의 배포 기록에서 관리한다. 버전 숫자만으로 배포·테스트 완료를 주장하지 않는다.

## 참고

- [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html): 호환성에 따른 버전 증가의 기본 원칙. 위 0.x 보수 규칙과 Web 적용 범위는 이 프로젝트가 추가로 정한 정책이다.
- [npm version (npm 11)](https://docs.npmjs.com/cli/v11/commands/npm-version/): workspace 버전 변경과 `--no-git-tag-version` 옵션.
